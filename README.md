# 有譜 Studio｜AI 輔助建站服務體驗（概念驗證）

**展示網址（GitHub Pages 須成功部署）**：https://shanpig.github.io/studio-website-demo/

> **現況聲明**：這是銷售提案與客戶旅程的**可操作 Demo**，並非目前已開業的網站設計公司。不提供即時真人客服、正式報價、金流或實際收件。沒有已成交的商業案例或真實客戶評價。任何計畫中的「真人把關」都須在正式服務啟動前確認責任人員及 SLA。

## 這一版驗證什麼？

核心假設：「客戶不是缺少能生成網頁的 AI，而是不想自己研究設計、反覆撰寫 Prompt、負責品質驗收、部署或資料處理。」

顧客旅程：
1. **先看範例**：四種真實可切換的視覺方向（留白、強烈、溫暖、專業）。
2. **挑選產業**：設計／顧問／生活服務／科技，搭配不同示例文案，形成 16 種基本對照。
3. **直接改預覽**：更換品牌名稱、主標題、CTA，並切換桌面與手機寬度。
4. **精準問答**：5 個單選問題，辨識產業、轉換目標、客戶疑慮、優先功能、素材成熟度。
5. **交付產出**：依選擇生成包含優先功能驗收條件、資安與素材待辦的完整 TXT 需求簡報。
6. **下一步**：作為人工服務的確認基礎，尚未開放付款或正式委託。

## 市場差異化實驗

| 比較 | AI 自行建站工具／通用模板 | 有譜 Studio 想驗證的服務 |
|---|---|---|
| 進站第一步 | 生成網站、輸入提示詞 | 先比較視覺樣本 |
| 需求描述 | 自己撰寫目標與 Prompt | 用客戶能理解的問題引導 |
| 迭代 | 自己判斷、改 Prompt、重試 | 有版本記錄及人員審核（**待啟動**） |
| 內容 | 客戶自己準備 | 明確辨識缺少素材與授權問題 |
| 表單、資料、安全 | 依工具與客戶能力 | 納入交付驗收標準（**待落實**） |
| 維護 | 依平台或自行維護 | 契約中定義移交與維護責任（**待落實**） |

NT$19,800 與 NT$39,800 是市場測試提案價格，**不是已接單的真實定價與交付承諾**。

## 檔案

- `index.html` — 產品首頁、體驗樣本、服務、價格、交付流程、FAQ
- `studio.css` — 響應式視覺系統和四種差異化樣本樣式
- `studio.js` — 桌面／手機預覽、樣本切換、五題引導式問答、在地生成的需求簡報
- `favicon.svg` / `icon.svg` — 品牌識別
- `tests/smoke.cjs` — 無套件依賴的靜態驗收檢查

舊版本的 `data.js` 和 `app.js` 是前一輪建築案例研究的歷史檔案，**不再從首頁載入**。

## 隱私與交付限制

本版問卷不連接任何 API、不寄信也不把答案上傳。下載檔案於訪客的裝置中生成。圖片使用示範性 Unsplash 外連，正式客戶網站須依照實際素材授權更換。若未來需要商業收件，需有正式隱私政策、個資蒐集依據、保存期限、刪除流程、防濫用、存取權限與合約責任。

品質參考：WCAG 2.2、web.dev Core Web Vitals、OWASP Web Security Testing Guide。這次增加了 skip link、語意化標題、可見焦點、44px 操作目標、reduce-motion 及真實可操作問答，但**尚未完成完整 Lighthouse、鍵盤端到端、跨瀏覽器或資安稽核**。

## 本地驗證

```bash
node tests/smoke.cjs
```

GitHub Actions 的 `main` 自動部署工作流程會先跑 smoke tests，再嘗試 GitHub Pages 部署。必須在 GitHub Pages Settings 中選擇 GitHub Actions source。
